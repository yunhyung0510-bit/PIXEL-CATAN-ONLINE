# 21. 온라인 멀티플레이 시스템

기존 CATAN AI 프로젝트에 실시간 온라인 멀티플레이 기능을 추가한다.

기존 싱글 플레이와 AI 대전 기능은 유지하면서 인터넷을 통해 여러 사용자가 같은 게임에 접속할 수 있도록 구현한다.

### 21-1. 서버 및 통신 구조

기술 구성:
- Node.js
- Express
- Socket.IO
- PostgreSQL
- React
- TypeScript

서버는 게임의 최종 권한을 가지는 구조로 제작한다.

클라이언트는 플레이어의 행동을 서버에 요청하고, 서버는 게임 규칙을 검증한 후 게임 상태를 변경한다.

변경된 게임 상태는 해당 게임방에 접속한 플레이어에게 실시간으로 전달한다.

게임의 핵심 로직은 서버에서도 실행할 수 있도록 독립적으로 설계한다.

### 21-2. 메인 메뉴 추가

메인 화면에 다음 메뉴를 추가한다.

1. 싱글 플레이
2. AI 대전
3. 온라인 멀티플레이
4. 게임 기록
5. 설정

온라인 멀티플레이를 선택하면 다음 화면으로 이동한다.

- 공개 게임 찾기
- 비공개 방 만들기
- 방 코드로 참가하기
- 친구 초대하기

### 21-3. 방 생성 시스템

방장은 새로운 게임방을 생성할 수 있다.

방 생성 설정:

- 방 이름
- 공개 또는 비공개
- 최대 플레이어 수
- AI 참가 허용 여부
- AI 난이도
- 게임판 설정
- 승리 점수
- 참가자 입장 제한

방이 생성되면 고유한 6자리 방 코드를 발급한다.

방장은 초대 링크와 방 코드를 복사할 수 있다.

방장은 게임 시작 전까지 다음 권한을 가진다.

- 플레이어 추방
- AI 추가 및 제거
- 게임 설정 변경
- 게임 시작
- 방 공개 여부 변경

### 21-4. 방 참가 시스템

플레이어는 공개 방 목록에서 원하는 방을 선택할 수 있다.

방 목록에 다음 정보를 표시한다.

- 방 이름
- 방장 이름
- 현재 참가 인원
- 최대 인원
- 게임 시작 여부
- 공개 또는 비공개 여부

비공개 방은 방 코드로만 입장할 수 있도록 한다.

이미 게임이 시작된 방에는 일반 참가자가 새롭게 입장하지 못하도록 한다.

### 21-5. 플레이어 준비 시스템

방에 입장하면 대기실을 표시한다.

대기실 구성:

- 플레이어 이름
- 플레이어 색상
- 인간 또는 AI 구분
- 준비 상태
- 연결 상태
- 방장 표시

각 플레이어는 준비 버튼을 눌러 게임 준비 상태로 변경할 수 있다.

방장은 모든 참가자가 준비되었거나 방장 권한으로 게임을 시작할 수 있는 조건이 충족되면 게임을 시작한다.

게임 시작 시 참가자 순서를 무작위로 결정한다.

### 21-6. 실시간 게임 동기화

게임 진행 중 발생하는 모든 주요 행동을 서버를 통해 동기화한다.

동기화 대상:

- 주사위 결과
- 자원 획득 및 소비
- 도로 건설
- 정착지 건설
- 도시 업그레이드
- 거래 제안
- 거래 수락 및 거절
- 발전 카드 구매 및 사용
- 도둑 이동
- 승점 변경
- 현재 턴 변경

한 플레이어가 행동하면 다른 플레이어의 화면에도 즉시 반영되어야 한다.

같은 행동이 여러 번 실행되지 않도록 행동마다 고유한 요청 ID를 부여한다.

### 21-7. 턴 관리

게임 서버가 현재 턴의 플레이어를 관리한다.

- 자신의 턴에만 행동 가능
- 주사위는 자신의 턴에만 굴릴 수 있음
- 건설은 규칙에 맞는 경우에만 가능
- 거래는 정해진 거래 단계에서만 가능
- 턴 종료 시 다음 플레이어에게 순서가 넘어감

각 플레이어의 행동 가능 여부를 서버에서 확인한다.

### 21-8. 온라인 거래 시스템

온라인 거래는 모든 참가자가 확인할 수 있도록 한다.

거래 진행:

1. 플레이어가 거래를 제안한다.
2. 거래 제안이 게임 화면에 표시된다.
3. 다른 플레이어가 제안을 확인한다.
4. 수락 또는 거절을 선택한다.
5. 수락 시 서버에서 자원 보유량을 다시 확인한다.
6. 문제가 없으면 거래를 처리한다.
7. 거래 결과를 모든 플레이어에게 전송한다.

거래 제안은 취소할 수 있어야 한다.

거래가 성립되기 전에 관련 플레이어의 자원이 변경되었다면 거래를 다시 검증한다.

### 21-9. AI와 인간의 혼합 대전

하나의 게임방에서 인간과 AI가 함께 플레이할 수 있도록 한다.

예시:
- 인간 1명 + AI 3명
- 인간 2명 + AI 2명
- 인간 3명 + AI 1명
- 인간 4명

AI는 서버에서 행동을 수행한다.

AI의 행동이 끝나면 다음 플레이어에게 자동으로 턴을 넘긴다.

AI가 인간 플레이어의 비공개 자원을 확인할 수 없도록 한다.

### 21-10. 연결 종료 및 재접속

인터넷 연결이 끊긴 플레이어를 감지한다.

- 연결 종료 상태 표시
- 재접속 버튼 제공
- 기존 플레이어 정보 유지
- 기존 자원과 승점 유지
- 기존 게임판 복원
- 진행 중인 턴 복원

플레이어가 일정 시간 동안 재접속하지 못하면 방장이 해당 플레이어를 AI로 대체하거나 게임에서 제외할 수 있도록 한다.

재접속 시 플레이어의 인증 정보를 검증하여 다른 사용자가 해당 계정을 대신 사용할 수 없도록 한다.

### 21-11. 관전 기능

게임이 시작된 방을 관전할 수 있도록 한다.

관전자에게 제공하는 정보:

- 게임판
- 공개된 플레이어 정보
- 승점
- 주사위 결과
- 게임 로그
- 현재 턴

관전자는 게임에 직접 개입할 수 없다.

상대방의 비공개 자원과 숨겨진 발전 카드는 관전자에게 표시하지 않는다.

### 21-12. 채팅 시스템

게임방 내부에 채팅 기능을 추가한다.

- 일반 채팅
- 시스템 메시지
- 거래 관련 알림
- 게임 시작 및 종료 알림

욕설 및 도배 방지를 위한 기본적인 제한을 적용한다.

채팅은 게임 화면을 가리지 않는 별도 패널로 배치한다.

### 21-13. 게임 데이터 보안

게임 서버를 최종 데이터 관리자로 설정한다.

클라이언트에서 임의로 자원이나 승점을 변경할 수 없어야 한다.

주사위 결과는 서버에서 생성한다.

각 플레이어에게는 자신의 비공개 자원 정보만 전달하고, 다른 플레이어에게는 공개 정보만 전달한다.

서버는 모든 요청에 대해 다음을 검증한다.

- 플레이어 인증
- 게임방 참가 여부
- 현재 턴
- 행동 가능 여부
- 자원 보유량
- 건설 위치
- 행동의 중복 여부

### 21-14. 데이터베이스

다음 정보를 저장한다.

Users:
- 사용자 ID
- 닉네임
- 계정 정보
- 가입 날짜

GameRooms:
- 방 ID
- 방 코드
- 방장 ID
- 공개 여부
- 게임 상태

GamePlayers:
- 게임 ID
- 플레이어 ID
- 플레이어 색상
- 참가 순서
- 준비 상태

GameRecords:
- 게임 ID
- 참가자
- 최종 승점
- 최종 순위
- 게임 시작 시간
- 게임 종료 시간

GameStates:
- 현재 게임판
- 플레이어 상태
- 자원 정보
- 도로 및 정착지 위치
- 발전 카드 정보
- 현재 턴
- 게임 진행 상태

비공개 게임 데이터는 권한을 확인한 후에만 전달한다.

### 21-15. 최종 테스트

다음 상황을 모두 테스트한다.

1. 4명의 인간 플레이어가 같은 방에 접속한다.
2. 2명의 인간과 2명의 AI가 함께 게임을 진행한다.
3. 한 명이 접속을 종료한 후 재접속한다.
4. 거래 제안과 수락이 모든 플레이어에게 반영된다.
5. 한 플레이어의 행동이 다른 플레이어 화면에 실시간 반영된다.
6. 다른 플레이어의 자원을 임의로 변경할 수 없다.
7. 같은 요청을 반복해도 자원이 중복 지급되지 않는다.
8. 게임 종료 시 모든 플레이어에게 동일한 승리 결과가 표시된다.

최종 목표는 친구들과 방을 만들어 실제 보드게임처럼 함께 플레이할 수 있는 온라인 카탄 스타일의 전략 게임을 완성하는 것이다.
